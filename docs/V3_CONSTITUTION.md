# TukTuk V3 — Конституция продукта

> **Исторический документ.** Написан на этапе V3, когда проект назывался TukTuk. Сейчас продукт называется **Qq** и представляет собой мессенджер один-на-один (BLE/DTN + опциональный Internet Gateway). Часть описанных здесь идей в продукт не вошла и отключена в Core-сборке (`QQ_CORE_ONLY`, см. `QqLegacyQuarantine`). Текст сохранён как история и не описывает текущий Qq. Актуальное описание продукта: [`../README.md`](../README.md).

Статус: **зафиксировано (фаза 0)**  
Продукт: гуманитарный мессенджер  
Слоган: связь там где есть люди

Этот документ — закон для всех следующих фаз.  
Если фича противоречит конституции — фича неверна.

---

## 1. Что такое TukTuk

TukTuk — не про Bluetooth.  
Не про Mesh.  
Не про Wi‑Fi.  
Не про VPS.

TukTuk — про людей.  
Технологии — лишь способ найти путь между людьми.

Пользователь думает только о сообщении.  
Пользователь не выбирает транспорт.

---

## 2. Запрещено

1. Копировать код Telegram.
2. Использовать библиотеки Telegram.
3. Использовать компоненты Telegram.
4. Использовать архитектуру Telegram.
5. Показывать пользователю инженерную информацию:
   - MAC-адреса
   - UUID
   - GATT / ACK / TTL как «фичу»
   - сырые технические статусы mesh
6. Делать геймификацию про деньги, NFT, крипту, уровни, ачивки.
7. Требовать от пользователя выбора пути отправки (Internet / VPS / Wi‑Fi / BLE).
8. Делать QR основным способом добавить человека (только дополнительный).

---

## 3. Разрешено

1. Анализировать Telegram / WhatsApp / Signal / iMessage как эталон UX.
2. Повторять пользовательские сценарии и логику поведения интерфейса.
3. Писать все компоненты заново, своим кодом.
4. Оставлять Delivery Observatory как **внутренний** источник данных для Tracker.
5. Хранить и развивать собственный Router и mesh/VPS ядро.

---

## 4. Контракт Router (нерушимый)

Любая отправка проходит **только** через `MessageRouter`.

Порядок попыток:

```
Internet (VPS)
  → Wi‑Fi Direct
    → BLE
      → Store & Forward
```

Правила:

- UI не выбирает транспорт.
- После подключения VPS пользователь не должен понимать, каким путём ушло сообщение.
- Падение одного пути не показывает «ошибку протокола» — показывает человеческий статус («ищем путь», «у людей», «друг получил»).

См. также: `docs/ROUTER_VPS.md`.

---

## 5. UX-закон

Пользователь не должен переучиваться.  
Если человек пользовался Telegram — он должен начать TukTuk без обучения.

Перед реализацией каждого UI-сценария:

1. Изучить Telegram / WhatsApp / Signal / iMessage.
2. Выбрать лучшее поведение.
3. Реализовать **своим** кодом.
4. Зафиксировать решение в `docs/V3_UX_BASELINE.md`.

---

## 6. Главные продуктовые поверхности

| Поверхность | Роль |
|-------------|------|
| Диалоги | Плотный список как у современного мессенджера |
| Чат | Максимум области сообщений, минимум ввода |
| Tracker | Главная особенность доставки: человеческая история пути |
| Сеть | «Живая» картина людей и потока, без техники |
| Экспедиция | Главная незавершённая функция: курьер / посылка / вклад / косметика |
| Каналы | Район / город / экстренные / локальные / служебные |
| Профиль | Статистика помощи сети |
| Настройки | Минимум, только TukTuk-необходимое |

---

## 7. Экспедиция — закон геймификации

Без Экспедиции продукт считается **незавершённым**.

Метафора:

- Сообщение = посылка
- Пользователь = курьер
- Телефон = узел сети

Награда только косметическая:

- темы
- рамки
- цвет ника
- значки
- аватары / украшения
- редкие динозавры

Главная эмоция после передачи:

> Я помог сети.

Не:

> Я получил достижение.

---

## 8. Контакты

Контакт один и тот же:

- найден через Internet → автоматически становится доступен в mesh-контексте;
- найден через mesh → при появлении Internet синхронизируется автоматически.

QR — дополнительная возможность, не основной онбординг.

---

## 9. Delivery Observatory

Оставить.  
Использовать как внутренний источник данных для Tracker.  
Не показывать пользователю инженерную панель как продукт.  
Пользователю — только понятная история доставки.

---

## 10. Definition of Done для любой фичи V3

Фича готова только если:

1. Не нарушает конституцию.
2. Не требует выбора транспорта.
3. Не показывает MAC / UUID / инженерный жаргон в пользовательском UI.
4. Имеет UX-заметку в baseline (для UI-сценариев).
5. Проходит DoD своей фазы в `docs/V3_PHASES.md`.
6. Имеет проверяемый результат (экран / сценарий / APK), а не «код ради кода».
