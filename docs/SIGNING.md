# Подпись APK (важно для обновлений)

Android разрешает «обновить поверх» **только** если SHA-256 сертификата совпадает.

Текущая версия продукта берётся из `versionName` в **`app/build.gradle.kts`** — это единственный источник истины; здесь номер сознательно не дублируется. Хронология тегов: [`VERSIONS.md`](VERSIONS.md).

Ярлыки `0.3.x` / `3.0` — из более раннего V3-поезда, не «новее» текущей линейки `0.1.N`.

## Текущий официальный ключ (с v0.3.2 и далее вся линейка 0.1.4+)

- Файл: `app/release.keystore` (gitignored)
- Alias: `tuktuk`
- SHA-256: `573c85663e25bf9afa379a076d4a194997bd99cbf6c94cc919c4b28e14c230c5`
- Бэкап паролей: `secrets/RELEASE_KEY_BACKUP.txt`

**Никогда не запускай** `FORCE=1 ./scripts/setup-official-signing.sh` — это создаст новый ключ и снова сломает обновления.

## Старые релизы (v0.2 … v0.3.1) — до смены ключа

Были подписаны **другим** ключом с тем же CN (`TukTuk Official` — историческое значение в сертификате, не переименовывается), SHA-256:

`4dff9ec22c9aa2700c7909d51efda6c4d459f13673944aa62a081768adc4327a`

Этот keystore на машине **не найден** (скорее пересоздан скриптом). Поэтому с APK той эпохи (≤0.3.1) нельзя обновиться на сборки с текущим ключом (`0.3.2`, затем вся линейка `0.1.4` и далее) без удаления — один раз удалить старое и поставить новый APK. Дальше обновления с тем же `release.keystore` ставятся поверх.
