# TukTuk V3 — UX Baseline

Статус: **живой документ**  
Правило: перед кодом UI-сценария — анализ 4 эталонов → выбор → своя реализация.

Эталоны: **Telegram · WhatsApp · Signal · iMessage**

Ниже — решения для TukTuk.  
Формат блока:

- Что сравниваем
- Что лучше у эталонов
- Решение TukTuk
- Что запрещено копировать (код/ассеты/архитектура)

---

## 0. Общий принцип

Лучшее = привычное поведение без обучения + гуманитарный характер TukTuk  
(доставка через людей, вклад в сеть, без техдемо).

---

## 1. Навигация (Shell)

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Корень | Чаты | Чаты | Чаты | Чаты |
| Вторичное | Contacts / Calls / Settings | Updates / Communities / Calls | Calls / Stories / Settings | в системе |

**Решение TukTuk:** 5 вкладок  
`Диалоги · Сеть · Экспедиция · Каналы · Профиль`

Почему:

- Диалоги = привычный корень мессенджера.
- Сеть = живая картина «люди рядом» (наша специфика).
- Экспедиция = главная незавершённая функция (курьер), не прятать в настройки.
- Каналы = публичные комнаты (район/город/экстренные…).
- Профиль = я + вклад в сеть + минимум настроек.

**Не делать:** вкладку «Mesh / BLE / Debug» как продукт.

---

## 2. Список диалогов

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Плотность | Очень высокая | Высокая | Высокая | Средняя |
| Поиск | Сверху, мгновенный | Сверху | Сверху | Сверху |
| Свайпы | Архив / mute / pin / delete | Архив / pin / mute / delete | Archive / pin / delete | Delete / mute |
| Непрочитанные | Бейдж + фильтры | Бейдж + фильтры | Бейдж | Бейдж |
| Закрепы | Да | Да | Да | Не в том же виде |

**Решение TukTuk (лучшее = Telegram-density + WhatsApp-свайпы):**

- Максимум диалогов на экран, минимальные отступы.
- Строка: аватар · имя · превью · время · бейдж непрочитанных.
- **Не** показывать raw id в основном ряду.
- Поиск сверху.
- Закрепы сверху списка.
- Архив через свайп.
- Фильтр «Непрочитанные».

**Запрещено:** карточки-стекло на каждую строку, если они уменьшают плотность.

## 3. Чат / композер

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Область сообщений | Максимум | Максимум | Максимум | Максимум |
| Высота ввода | Компактная, auto-grow | Компактная | Компактная | Компактная |
| Reply | Сверху композера | Сверху | Сверху | Quote bubble |
| Multi-select | Long-press → панель | Long-press | Long-press | Edit menu / select |

**Решение TukTuk:**

- Максимальная область сообщений.
- Минимальная высота поля ввода + auto-grow до ~5 строк.
- Действия: ответ · пересылка · копирование · удаление · редактирование · выделение нескольких.
- Long-press → собственное меню / bottom sheet (не системный Alert как единственный путь навсегда).

**Запрещено:** толстый композер, съедающий половину экрана.

---

## 4. Контекстное меню / bottom sheet

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Long-press | Контекст + реакции | Контекст + реакции | Контекст + реакции | Контекст |

**Решение TukTuk:**

- Long-press на сообщение → собственный bottom sheet.
- Реакции отдельным рядом (фаза реакций).
- Без резких появлений: лёгкий fade/slide, цель 60 FPS.

---

## 5. Tracker доставки (уникально TukTuk)

У эталонов: галочки / «delivered» / иногда «read».  
У TukTuk этого мало — путь через людей важнее галочки.

**Решение TukTuk:**

После тапа по сообщению пользователь **обязан** увидеть:

- кто принял
- кто переслал
- каким путём (человеческими словами: интернет / ближайший Wi‑Fi / люди рядом)
- сколько времени
- сколько остановок
- историю полностью

Источник данных: Delivery Observatory (скрыт).  
Язык: только человеческий.

**Запрещено:** ACK, GATT, UUID, MAC, «TTL exhausted».

---

## 6. Вкладка «Сеть»

Аналогов у TG/WA почти нет (ближе к status/nearby у некоторых продуктов).

**Решение TukTuk:**

Живая вкладка:

- живые соседи (имена, не адреса)
- активные передачи
- количество сообщений / очередь
- текущий путь (авто)
- статус сети словами слогана

**Запрещено:** debug-панель как основной UI.

## 7. Контакты

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Онбординг | username / телефон / QR | телефон | телефон / username | телефон / Apple ID |
| QR | Доп. | Доп. | Доп. | — |

**Решение TukTuk:**

- Контакт один: internet ↔ mesh синхронизация автоматическая.
- QR — дополнительный.
- Незнакомец → запрос в диалог (как message request у Signal/Telegram), Accept в UI.

---

## 8. Каналы

Ближе к Telegram channels/groups + локальные доски сообщества.

**Решение TukTuk (первичные группы):**

1. Экстренные  
2. Город  
3. Район  
4. Локальные  
5. Служебные  

Остальные комнаты — вторичный ряд.  
Wire-id комнат не ломать без миграции.

---

## 9. Профиль и настройки

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Профиль | Я + много настроек | Я + настройки | Я + приватность | Система |
| Настройки | Очень много | Много | Много, но яснее | Система |

**Решение TukTuk:**

- Профиль: аватар, ник, вклад в сеть (передано / получено / спасено / активность).
- Настройки: минимум (язык, обои, режим батареи/сети, VPS URL если нужен).
- Не превращать профиль в dump ID/ключей. ID — по тапу/копированию, не герой экрана.

---

## 10. Экспедиция (геймификация)

Эталоны мессенджеров этого почти не делают.  
Ближе по эмоции: «streak помощи» / вклад сообщества, но **без** ачивок Duolingo.

**Решение TukTuk:**

- Отдельная вкладка.
- Рабочее имя после UX: **Экспедиция** (не «Миссии», не «Доставка» как вкладка — доставка = Tracker).
- Показывает: ждут · передал · соседи помогли · очередь · вклад · косметика.
- Награда = только косметика.
- Эмоция = «я помог сети».

---

## 11. Реакции и стикеры (фаза 9)

| | Telegram | WhatsApp | Signal | iMessage |
|---|----------|----------|--------|----------|
| Реакции | Быстрые emoji | Быстрые | Быстрые | Tapback |
| Стикеры | Свои паки / TG API | Свои | Свои | Apple |

**Решение TukTuk:**

- Своя система реакций (без TG API).
- Свой формат стикеров (без TG stickers).
- Long-press → ряд реакций + действия.

---

## 12. Анимации (фаза 9)

Эталон: плавность iMessage/Telegram, без резких jump-cut.

**Решение TukTuk:**

Свои анимации:

- открытие / закрытие изображения
- ответ
- реакция
- появление / удаление сообщения

Цель: 60 FPS, никаких резких переходов.
